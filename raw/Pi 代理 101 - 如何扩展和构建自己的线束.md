你最近可能经常听到“Pi”这个词——它是 OpenClaw 最初的动力来源，OpenClaw 可能是有史以来增长最快的代理项目。

![Image](https://pbs.twimg.com/media/HMnrzu1aAAA4yj-?format=png&name=large)

Pi 的默认设置非常精简，仅包含四个工具：**bash、读取、写入和编辑** 。没有子代理、没有团队、没有 MCP。其他所有功能都需要您自行添加，而添加方式正是 Pi 的核心： **扩展** 。

## 扩展系统

几乎所有内容都可以自定义：工具、钩子、模型提供程序、会话管理、命令以及终端用户界面本身。Pi 了解自己的扩展 API，因此您通常可以省去编写代码的步骤。只需告诉 Pi “在我的提示符输入框中显示天气”，它就会读取扩展文档、写入控件并重新加载。

![Image](https://pbs.twimg.com/media/HMnsa3ybwAAM7ek?format=png&name=large)

扩展程序是一个 TypeScript 文件，它与框架连接。Claude Code 也有连接，所以区别在于连接范围。Pi 通过三个对象暴露了几乎所有连接：

- **pi.\*** 注册新功能：registerTool、registerCommand、registerShortcut、registerProvider（您自己的 LLM）、sendUserMessage、setActiveTools。
- **pi.on(event)** 对整个生命周期做出反应：输入、会话开始、代理开始前、工具调用、工具结果、上下文、提供程序请求前、会话压缩前。
- **ctx.\*** 访问实时会话：ctx.ui、ctx.sessionManager、ctx.cwd、ctx.model。

同时，**/reload** 可以实现热重载，因此代理可以在你使用它时重写自己的框架。

**示例 - TUI 自定义：** 我可以重新设计我的树莓派 TUI 界面 - 只需在 session\_start 时调用一次 ctx.ui.setHeader(...) 即可。或者在提示输入框上方添加天气信息。

![Image](https://pbs.twimg.com/media/HMnvzhFagAAwreV?format=jpg&name=large)

**例如 - 在终端中玩 DOOM：** 即使代理程序运行，你仍然可以玩 DOOM。有人把它打包上传到了……[pi.dev/packages/pi-doom](https://pi.dev/packages/pi-doom) 在你的编码会话中安装一个完整的 TUI 游戏，简直太疯狂了。

![Image](https://pbs.twimg.com/media/HMnwWYCaMAAg61g?format=png&name=large)

**真实案例 - pi-hypa：** 将工具标记切割 80~96%。[@hypabolic/pi-hypa](https://x.com/@hypabolic/pi-hypa)hooks 直接清理 bash 命令的输出。

例如，如果 pi 运行 \`git log --stat -200\`，它会清除诸如 diff、subject、comments 等不必要的信息，只保留 commit，这通常可以减少 80% 到 98% 的数据量。它会透明地拦截 Pi 的常规 bash 工具，因此代理程序不会请求压缩，也不会看到那 34k 个无用标记。

## How to build extensions

It's actually very easy to build Pi extensions, here are some examples:

1. Inject context. Make the agent Git-aware without a single tool call:

```text
pi.on("before_agent_start", (event, ctx) => {
  return { systemPrompt: event.systemPrompt + "\n\n" + gitSummary() };
});
```

Ask "what branch am I on? use no tools" and it already knows.

2\. Add a tool. Let the agent read your clipboard:

```text
pi.registerTool({
  name: "read_clipboard",
  description: "Read what's currently in the clipboard",
  execute: async () => ({ content: [{ type: "text", text: await clipboard.read() }] }),
});
```

With this Pi can have access to a new tool 'read\_clipboard'

3\. Permission gate

I run this on my team's shared agent, because not everyone should see everything. Before a prompt reaches the agent, a cheap Haiku call classifies it against a PERMISSION.md policy and either allows or denies it:

```text
import { complete } from "@earendil-works/pi-ai";

pi.on("input", async (event, ctx) => {
  const policy = await readPolicy(ctx.cwd);
  if (!policy) return { action: "continue" };
  const { decision, reason } = await classify(ctx, policy, event.text); // Haiku
  if (decision === "denied") {
    ctx.ui.notify(\`Blocked by PERMISSION.md: ${reason}\`, "error");
    return { action: "handled" };   // skip the agent entirely
  }
  return { action: "continue" };
});
```

I set the policy like "only Jason can see revenue data" and asked "what's June revenue?" as someone else. Pi blocked it before it reached the agent and showed the reason in the UI.

## Use Pi SDK to build real AI apps

Most people miss that Pi is more than a CLI. It's five packages: pi-ai (call any model, with Claude and Codex subscription OAuth), pi-agent (the core loop), pi-coding-agent (the Claude Code SDK equivalent, with tools, sessions, compaction, extensions), the TUI, and an orchestrator. The whole agent collapses into a function call.

![Image](https://pbs.twimg.com/media/HMnyo3yaEAAJWtM?format=jpg&name=large)

Here's the agent in about 15 lines, no UI:

```text
import { createAgentSession, SessionManager } from "@earendil-works/pi-coding-agent";

const { session } = await createAgentSession({
  sessionManager: SessionManager.inMemory(),
});

session.subscribe((event) => {
  if (event.type === "message_update" && event.assistantMessageEvent.type === "text_delta") {
    process.stdout.write(event.assistantMessageEvent.delta);   // stream to your UI
  }
});

await session.prompt("Look at the files here and tell me what this project is.");
```

Run npx tsx and watch it stream, using your existing Pi auth (your Claude subscription, no API key in the file). Wrap that same session in a WebSocket and you have a hosted chat agent, one session per browser tab.

For a product you scope each session with a resource loader and your own tools:

```text
const resourceLoader = new DefaultResourceLoader({
  cwd,                                  // where the agent WORKS (a per-user sandbox)
  agentDir: getAgentDir(),              // config/auth root, stays on the host
  noExtensions: true, noSkills: true,   // deny ambient pickup, allow only what you pass
  extensionFactories: [guardrail],      // policy as code (e.g. block dangerous bash)
});
await resourceLoader.reload();

const { session } = await createAgentSession({
  sessionManager: SessionManager.inMemory(),
  customTools: [getMrr],                // your product's own capabilities
  resourceLoader,
});
```

I used this exact shape to build Posia, an autonomous agent that launches and runs a business. Going web-hosted instead of local costs you one adjustment: Pi's defaults assume a local filesystem, with sessions as JSONL and tools running on the host.

For a multi-tenant backend you run SessionManager.inMemory(), treat your own DB as the source of truth by mirroring session.subscribe, and re-back bash, read, and write through each user's sandbox.
