DeepSeek 也做 Agent 了，而且一出手就是开源。

8 月 13 日开源的 DeepSeek Harness（简称 DSH），两个多月涨到 25.6 万 Star。一句话说清它是什么：**DeepSeek 网页版只会回答问题，DSH 能让模型在你的电脑上动手干活，而且每一个零件都能拆下来换掉。**

它强在三点：

- **门槛低**：不用梯子、不用 API Key，DeepSeek 账号登录就能用，跑一个普通 demo 也就几毛钱；
- **能改造**：一切皆插件，连 Agent 循环都能换，社区插件已经有 6000 多个；
- **看得见**：每一步都能在「轨迹」里回放，连塞给模型的隐藏上下文都看得到。

要提防的是：它还是预览版，更新经常破坏兼容，也没做过安全审计。

我 8 月就开始用 DSH，在 X 上零散写过不少，却一直没找到一篇小白能从下载跟到插件市场的完整讲解，这次干脆自己串成一篇。

# 一、先搞懂：Harness 到底是什么

## 1\. 模型是大脑，Harness 是身体

一个 AI Agent 可以粗略拆成两部分：

> 模型负责“想”：理解你的话、判断下一步做什么；

> Harness 负责“做”：把模型接到文件、终端、浏览器和各种工具上，管理对话历史、权限确认、上下文压缩，再把结果交还给你。

同一个模型，接进不同的 Harness，干活水平可以差很多。Claude Code、Codex、Pi、OpenCode 本质上都是 Harness。我之前翻译过一篇 [从零开始理解 Agent Harness](https://x.com/xiaomovps/status/2105516481887027446)，想补概念的可以先看那篇。

DeepSeek Harness 的定位写得很直接：**它是一个开源的 agent harness（智能体框架），不是模型。**

## 2\. 一切皆插件：连“大脑和身体的连接方式”都能换

市面上大部分 Agent 是“整机”：你能装 Skill、接 MCP，但核心那一圈——模型怎么调用、工具怎么执行、对话怎么存、Agent 循环怎么跑——是厂商写死的。

DSH 反过来。它底层用的是一个叫 Cordis 的插件框架，官方架构文档原话是：

> 产品的每一部分都是插件，包括模型适配器、工具注册表、会话日志，以及 agent loop（智能体循环）本身，因此每个都可以从配置替换。

> 不存在需要打补丁的特权内核。

翻译成人话：

- **模型适配器是插件**：今天接 DeepSeek，明天换 Kimi、GLM、Claude，改配置就行；
- **工具是插件**：读文件、跑 Bash、搜索、定时任务，每个都能单独开关；
- **会话存储是插件**：对话记录怎么存、存在哪，可以换；
- **Agent 循环本身也是插件**：模型“想一步、做一步”的那个主循环，也能整个替换；
- **界面也是插件**：侧边栏里的一个入口、一个标签页，也是某个插件贡献的。

而且这些插件可以在运行中装上、卸下。The Register 的报道专门提到这一点：VS Code 换扩展经常要重启宿主，DSH 的设计目标是拔掉一个零件，整机照常运转。

## 3\. 丑话说在前面：它还是预览版

这套设计在开发者圈子里评价不低。Flask 作者、知名开源开发者 Armin Ronacher 说这个思路 “felt quite inspired（很有启发性）”。它也不绑定 DeepSeek 模型，Anthropic、OpenAI、Kimi、GLM 和 OpenAI 兼容的中转站都能接。

但热度归热度，**DSH 目前仍是预览版。** 官方 README 写着「未来将出现破坏兼容性的变更」，安全说明里也写明「尚未接受安全审计，不得视为安全或可用于生产环境的软件」。你可以放心学、放心玩，但别一上来就拿它碰公司核心资料。

# 二、下载、登录和第一次对话

## 1\. 从官网下载桌面版

打开 [DeepSeek Harness 官网](https://www.deepseek.com/harness/)，点击「下载 macOS 版」，Windows 用户点按钮右边的下拉箭头找对应版本。目前提供两个版本：

- **macOS（Apple 芯片）**
- **Windows（64 位）**

桌面版里跑的就是完整的 DSH，功能和网页版一致。装好、打开，下一步登录。

## 2\. 登录：用 DeepSeek 账号最省事

第一次打开，输入框右下角显示「请选择模型」，说明还没有可用的模型。点击左下角头像，选择「登录」。

![Image](https://pbs.twimg.com/media/HVKkVSeXEAAYaGx?format=jpg&name=large)

它会打开浏览器，进入 DeepSeek 账号登录页。已经在网页版登录过的话，这里会直接显示你的账号，点「登录」即可。

![Image](https://pbs.twimg.com/media/HVKkVScXsAAMPg1?format=png&name=large)

**注意页面顶部那行提示：**

> 请确认你信任当前客户端。完成登录后，它将获得调用 DeepSeek 模型的账号授权，来源不明或经修改的客户端可能滥用授权凭证，产生未经授权的调用及费用。

翻译成人话：**登录以后，DSH 调用模型花的是你账号里的钱。** 所以只在官网下载的客户端上登录，别在来路不明的“魔改版”上登。

![Image](https://pbs.twimg.com/media/HVKkw4SbQAAMSLk?format=jpg&name=large)

看到「登录成功」，点「打开应用」回到桌面端。

## 3\. 账号和 API Key，两种用模型的方式

登录以后，打开 **设置 → 账号与余额**，能看到充值余额、赠金余额，旁边有「查询用量」和「充值」。用多少、还剩多少，在客户端里就能看。

![Image](https://pbs.twimg.com/media/HVKkVSiW0AAzASY?format=png&name=large)

再打开 **设置 → 模型**，会看到两张卡片：

- **DeepSeek 账号**：显示「已登录」，走的就是刚才登录的账号；
- **DeepSeek**：填 API Key 的方式。如果你电脑上已经配过 DEEPSEEK\_API\_KEY 环境变量，它会直接提示「已检测到环境变量」，留空即可使用。

![Image](https://pbs.twimg.com/media/HVKkVSfXIAAQBQJ?format=png&name=large)

![Image](https://pbs.twimg.com/media/HVKkVZuXsAE3kcY?format=png&name=large)

小白选一种就够了：**个人体验直接用账号登录；已经在开放平台充过值、或者要接其他工具的，用 API Key。**

API Key 有两个让人放心的设计：密钥是只写的，保存以后页面只显示打码后的描述；密钥单独存在 ~/.dsh/.credentials.yaml，普通设置文件里只保留一个引用。

想接其他模型，点「添加模型提供商」。Anthropic、OpenAI、Kimi（moonshotai）、GLM（zai）都在内置列表里；中转站、公司网关选「自定义模型 API」，支持 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages 三种协议。

## 4\. 认清主界面

登录完成，主界面长这样：

![Image](https://pbs.twimg.com/media/HVKkVZ8XwAAaYsc?format=jpg&name=large)

左侧从上到下是：

- **新会话**：所有任务从这里开始；
- **插件**：管理已经装上的插件；
- **插件市场**：浏览和安装社区插件（这个入口是装了社区插件 dshmarket 以后才出现的，新手不装也行，第四部分细讲）；
- **自动化任务**：查看和管理定时任务；
- **工作区**：DSH 能读、能改的文件夹列表。

工作区是这里最重要的概念。**它就是 DSH 这次能动的地盘。** 桌面版自带一个「默认工作区」，但我建议点「工作区」右边的新建图标，单独添加一个练习文件夹。我这里建了一个 harness-case，第一次别直接把整个桌面或下载文件夹交出去。

## 5\. 发出第一句话

新建会话，问一句最简单的：「你是什么模型？」

![Image](https://pbs.twimg.com/media/HVKkVaKW0AAqfRi?format=jpg&name=large)

它回答自己是 deepseek-flash 驱动的编程智能体，运行在 DeepSeek Harness 里，能读写文件、运行命令、检索代码、执行多步骤任务。

**这里有个细节值得多看一眼：** 回复下面写着「用量 9.2K tok」，输入框下方的状态栏显示「1 轮 1 步 · 239 tok/s · 9.2K tok · 缓存命中 4%」。

我就问了 6 个字，为什么用了 9200 多个 token？因为每次请求，DSH 都会把系统提示词、工具说明、技能目录、当前时间和工作目录一起发给模型。这些东西你在对话页看不到，但在第三部分要讲的「轨迹」里，全都能看到。

## 6\. 用一次要花多少钱

DSH 本身免费开源，花钱的是模型调用：按 token 计费，从你的 DeepSeek 余额里扣，有赠送余额时优先扣赠送余额。

下面是 DeepSeek 官方价格页上两款模型的价格，单位是每百万 token、人民币：

| 计费项 | DeepSeek-V4.1-Flash | DeepSeek-V4-Pro |
| --- | --- | --- |
| 输入（缓存命中） | 0.02～0.04 元 | 0.15～0.30 元 |
| 输入（缓存未命中） | 1～2 元 | 4.5～9 元 |
| 输出 | 4～8 元 | 13.5～27 元 |

每格前一个数是空闲时段价，后一个数是高峰时段价。高峰时段是北京时间工作日 9:00～12:00 和 14:00～18:00，其余时间（包括周末和法定节假日）都是空闲时段，价格是高峰的一半。

「缓存命中」指的是和之前请求重复的那部分内容，比如每次都要发的系统提示词。以 Flash 为例，命中缓存的输入比没命中便宜 50 倍。

换算成体感：

- 上面那句「你是什么模型？」用了 9.2K token，按 Flash 高峰价粗算，大约 2 分钱；
- 我自己让它跑一个普通 demo，读几个文件、写几个文件，也就几毛钱；
- 真正费钱的是长任务：轮数一多，每轮带的上下文越滚越大，再切到 Pro，花费会明显上去。

三个省钱习惯：

1. 日常用 Flash，材料多、步骤长的任务再切 Pro；
2. 不着急的大批量任务，放到晚上或周末跑，直接半价；
3. 隔几天去 **设置 → 账号与余额** 点「查询用量」，看看钱花在哪。

还有一个时间点要记住：官方价格页写明，在 DSH 里使用 DeepSeek API 时触发的网页搜索和抓取，目前不收费，**从 2026 年 11 月 1 日起按次收费**，每 1000 次成功请求 5 元。

价格随时可能调整，以 [DeepSeek 官方价格页](https://api-docs.deepseek.com/zh-cn/quick_start/pricing) 为准。

## 7\. 开发者也可以用命令行启动

装了 Node.js 的人，不想装桌面版，也可以在项目文件夹里运行：

```sh
npx @deepseek-ai/dsh web
```

它会在 http://127.0.0.1:3080 启动网页版并自动打开浏览器。你在哪个文件夹运行这条命令，DSH 就把哪个文件夹当成默认工作位置。

想改源码、写插件的，再去 [GitHub 仓库](https://github.com/deepseek-ai/deepseek-harness) 克隆源码运行。第一次体验，用桌面版就够了。

# 三、输入框这一排，先全部翻译成人话

DSH 的入口很多，但小白每天真正会碰的，基本都在输入框附近。我先给你翻译一遍：

- **工作区（\`harness-case\`）**：这次对话在哪个文件夹里干活；
- **标准模式**：这次对话带哪套工具上场；
- **+**：添加附件；
- **工作区内修改**：它能改到哪一步、什么时候要先问你；
- **DeepSeek-V4.1-Flash**：这次用哪个模型；
- **High**：推理强度，控制模型想得多深；
- **输入框里的 \`/\` 和 \`@\`**：/ 调用指令，@ 引用文件或之前的对话。

下面一个一个讲。

## 1\. Agent 模式：决定这次对话带哪套工具上场

点击工作区右边的「标准模式」，会弹出四种内置模式：

![Image](https://pbs.twimg.com/media/HVKkVaKXEAAieeU?format=jpg&name=large)

| 模式 | 官方说明 | 什么时候用 |
| --- | --- | --- |
| 标准模式 | 处理代码、文件和资料，适合大多数任务。Agent 会按需使用检索、编辑和终端等工具 | 默认就用它 |
| PTC 模式 | 包含标准模式的所有能力，更适合批量调用工具，并对结果进行筛选、整理、去重、统计或汇总的任务 | 批量处理一堆文件、一堆网页 |
| 极简模式 | Agent 使用终端和图片读取工具，并支持上下文压缩，适合测试和对比其基础表现 | 想测模型裸能力时 |
| 创造模式 | 用对话定制 DSH：让 Agent 编写插件，添加新功能或界面；也能组合工具和提示词，创建自己的模式 | 想给 DSH 加功能时 |

这四种模式在 **设置 → Agent 预设** 里也能看到。标准模式标着「新任务默认」，每张卡片下面都有「模式说明」和「如何使用」。最下面还有一个按钮：**让 Agent 帮我创建预设模式**。

![Image](https://pbs.twimg.com/media/HVKkVdBXAAEKt0P?format=jpg&name=large)

这就是 DSH 和别家最不一样的地方。别的 Agent 是“你用它干活”，DSH 的创造模式是“你让它改它自己”，连模式本身都能让 Agent 帮你造一个。

**模式不是越高级越好。** 普通读文件、改文档，标准模式完全够用；极简模式少了文本读写和编辑工具，拿来干日常活反而更费劲。

## 2\. 权限：决定它执行到哪一步必须停下来问你

点击输入框左下角的「工作区内修改」，有三档：

![Image](https://pbs.twimg.com/media/HVKkVe6XMAANo7v?format=jpg&name=large)

- **仅可查看**：只读不写。第一次接触陌生项目、只想让它帮你看看时用；
- **工作区内修改**：**这是默认档**。它可以修改你选中的工作区里的文件，碰到需要审批的操作会先问你；
- **完全权限**：不受工作区限制。选它时界面会额外弹一次风险确认。

还有第四档「自动审查」，默认看不到。它来自实验性插件「自动授权审查」：**由模型在每次工具调用前判断是否授权**，减少你手动点确认的次数。开启以后它只对当前会话生效，不能设成默认值。

新会话默认用哪一档，在 **设置 → 通用设置 → 权限** 里改。

我的建议：第一周就待在「工作区内修改」，把练习文件夹当成它唯一的地盘。看到删除、覆盖、批量改名、git push 这类操作弹出审批时，先读清楚对象和范围再点同意。

## 3\. 模型与推理强度：第一次保持默认就够了

点击右下角的模型名，会看到两组：

![Image](https://pbs.twimg.com/media/HVKkVg2WIAAXIo5?format=jpg&name=large)

- **DeepSeek 账号**：走账号余额的 DeepSeek-V4.1-Flash 和 DeepSeek-V4-Pro；
- **DeepSeek**：走 API Key 的同两款模型。

Flash 后面那个蓝色的「1017」是版本标记。两款模型可以这样分工：

- **DeepSeek-V4.1-Flash**：默认模型，响应快。日常整理文件、改文档、问答都用它；
- **DeepSeek-V4-Pro**：材料多、步骤长、需要综合判断的任务再切过来。

模型名右边的「High」是推理强度，有 Off、Low、High、Max 四档：

![Image](https://pbs.twimg.com/media/HVKkVlAXgAA2-jv?format=jpg&name=large)

模型和推理强度是两个独立选项：前者决定“谁来想”，后者决定“想多深”。改格式、换个说法这种小事，Low 就够；复杂研究、跨文件核对再开 Max。**高强度不会自动修正错误，任务完成后仍然要自己核对。**

## 4\. 计划模式：先出方案，你点头再动手

标准模式里内置了一个计划模式。进入以后，DSH 只会读文件、搜代码、做分析，**不会改任何东西**，最后把方案交给你审批。

它的规则写得很严：你在对话里说一句“好的”“可以”，**不算批准**；必须通过界面上的批准动作，它才会退出计划模式开始执行。

这对小白很友好。任务一大，先让它出计划，比做完再返工省事得多。

## 5\. 技能：自动发现你电脑上已有的 Skills

技能就是一份写给 AI 的工作说明书，格式是一个文件夹里放一个 SKILL.md。DSH 会自动扫描下面几个位置：

| 位置 | 说明 |
| --- | --- |
| 项目/.dsh/skills | 只给这个项目用的 DSH 技能 |
| 项目/.agents/skills | 项目里通用的 Agent 技能 |
| ~/.dsh/skills | 你自己的 DSH 全局技能 |
| ~/.agents/skills | 你自己的通用 Agent 技能 |

**看到第二行和第四行了吗？** 如果你之前已经在 .agents/skills 里放过 Skills（很多 Agent 工具都认这个目录），DSH 打开就能看到，不用重新安装一遍。新增、改名、删除技能也不用重启，下一次对话就生效。

桌面版还自带一组 Office 技能。我在轨迹里看到，它这次塞给模型的技能目录里有 7 个：office、office-docx、office-xlsx、office-pptx、office-export-pdf、office-recalculate 和 office-render，覆盖 Word、Excel、PPT 的创建、编辑、校验，以及导出 PDF。

两个小坑提前说：

1. 只认**一层**目录。skills/写作/SKILL.md 能识别，skills/分类/写作/SKILL.md 不行；
2. SKILL.md 开头必须写 name 和 description，name 要用小写加短横线（比如 weekly-report），格式不对会被直接跳过。

**“列表里能看见”和“能完整执行”是两件事。** 纯写作规则、步骤模板类的技能一般能直接用；依赖某个 Agent 专属工具、命令或固定路径的技能，换到 DSH 里还是要实际跑一遍。

## 6\. 自动化任务：让它按时间自动再跑一遍

点击左侧「自动化任务」，第一次打开是空的，页面上写着：

> 还没有自动化任务，在会话中创建的任务会显示在这里。

![Image](https://pbs.twimg.com/media/HVKkVjVX0AEA5xR?format=png&name=large)

这句话说明了 DSH 定时任务的用法：**直接在对话里说。** 比如：

```text
每天 Asia/Shanghai 时区 23:00 提醒我查看天气。
```

模型会调用内置的定时工具把它存下来，之后就会出现在这个页面里，可以按「全部、已开启、已结束」筛选，也能修改名称、指令和运行时间。右上角的「新建」，会开一个新会话，帮你把创建请求写好。

它支持的时间写法相当全：多少秒以后、某个具体日期时间、每隔 N 分钟（最少 1 分钟）、每天几点、每周几几点，以及标准的 cron 表达式。

创建完别急着走，回到这个页面点开刚建的任务，**检查频率是不是“每日”、时区是不是你要的那个**，而不是只执行一次。

两个限制要知道：**极简模式没有定时工具；被委派出去的子智能体也看不到定时工具。**

**手动跑一次完全正确，再把它变成定时任务。** 提示词错一次，手动任务只错一次；定时任务会每天错一遍。

## 7\. 轨迹：Agent 的“行车记录仪”

这是我最喜欢的一个入口。每个会话顶部都有两个标签：「对话」和「轨迹」。

![Image](https://pbs.twimg.com/media/HVKkVkRXgAAqSxG?format=jpg&name=large)

DSH 把每一次对话的所有细节**按顺序追加记录**，只增不改。轨迹页就是把这份记录摊开：上面是一条按「输入、模型、工具」分层的时间轴，下面是逐条记录。

还是刚才那句「你是什么模型？」，在轨迹里能看到，模型实际收到的是这样一串东西：

1. **系统**：初始系统提示词；
2. **用户**：你是什么模型？
3. **上下文**：当前运行环境，包括工作目录；
4. **上下文**：技能目录，也就是上面那 7 个 Office 技能；
5. **上下文**：当前时间和浏览器时区（Asia/Shanghai）；
6. **助手**：最后的回答。

那 9.2K token 就是这么来的。点开任意一条，右边会显示「概述、预览、原始内容、来源」，还能看到每一步的耗时和 token 用量。

**为什么这很重要？** 用其他 Agent 时，任务失败了你往往只能看到一句“出错了”。在 DSH 里，你能精确看到是第几轮、哪个工具、拿到了什么结果才出的问题。这份记录还支持恢复会话、从某一步分叉（fork）出新会话、搜索和回放。

轨迹标签由 **设置 → 通用设置** 里的「显示代码工作视图」控制，它的说明是：开启后，显示轨迹、本轮代码差异，可选择完整的 Agent 预设切换。会话顶部没看到「轨迹」，先检查这个开关。

## 8\. 设置页里还值得看的两处

![Image](https://pbs.twimg.com/media/HVKkVkfWAAE09Hf?format=png&name=large)

**通用设置**里，除了权限和语言，还有两个很实用的选项：

- **工作步骤展示**：选择希望看到多少工具调用细节；
- **工作步骤收起时机**：默认回答结束后自动收起，不想错过细节可以改掉。

**内置插件**页会按 Agent 模式列出当前会话用到的所有插件。这一页就是“一切皆插件”最直观的证据：

![Image](https://pbs.twimg.com/media/HVKkVk-XgAAuQuE?format=jpg&name=large)

- persona：智能体角色设定；
- agent-instructions：读取 AGENTS.md、CLAUDE.md 等文件，为 AI 提供工作区规则；
- time-context：每一步把当前时间、时区告诉模型；
- tool-bash、tool-fs、tool-fs-search：命令行、文件读写和文件搜索；
- tool-jobs、tool-schedule：后台任务和定时任务；
- 本地技能加载：从本地目录发现和读取技能。

注意第二条。**如果你的项目里已经写过 AGENTS.md 或 CLAUDE.md，DSH 会直接读。** 之前给 Codex、Claude Code 写的项目规则，换到 DSH 里不用重写。

右上角的「打开配置文件」，打开的是 ~/.dsh/profiles/\<profile>/cordis.patch.yml。你在设置页做的所有修改，最后都写进这个文件，第五部分会讲它为什么重要。

# 四、插件：DSH 真正的灵魂

前面讲的模式、工具、技能、定时任务，本质上都是插件。这一部分讲怎么管理插件、怎么找到好插件。

## 1\. 插件页：先看官方给了什么

点击左侧「插件」，页面分三块：

**内置插件配置**：

- **子智能体**：设置子智能体的递归层级、数量和模型；
- **网页搜索**：设置 DeepSeek 的搜索提供方；
- **Agent 循环**：控制 Agent 派发工具调用的方式；
- **终端**：限制每条命令最多能跑多久、最多输出多少内容。

**实验性插件**：默认关闭，点右边开关启用。首页只露出智能体团队、语音输入、自动授权审查、开发者工具等几个，点右上角「更多」能看到完整列表，还有 Git 工作树、思考过程机器翻译、持久终端、会话搜索、Ralph 循环等。

**已安装插件**：你自己装的第三方插件。

另外，官方仓库里还有两个按需安装的组合包：**Claude Code 子智能体** 和 **Codex 子智能体**。启用以后，DSH 可以把一个独立的子任务，交给你电脑上的 Claude Code 或 Codex 在同一个工作区里跑一遍，跑完只把最终答案交回来。**DSH 可以当“包工头”，把活分包给别家的 Agent。**

## 2\. 官方插件市场：新手首选，加一个索引地址就能逛

DSH 没有内置任何插件来源，但官方留了一个口子：实验性插件「自定义插件市场」。打开它，插件页会多出一个「发现」标签页；你给它一个插件索引的地址，就能在 DSH 里直接浏览和安装索引里的插件。

在插件页的「实验性插件」右上角，点「更多」：

![Image](https://pbs.twimg.com/media/HVKkVnVXEAAv-Nr?format=jpg&name=large)

拉到最下面，打开「自定义插件市场」的开关。它的说明是：在插件页添加「发现」标签页，从你添加的插件市场索引浏览和安装插件。

![Image](https://pbs.twimg.com/media/HVKkVqcXcAANh02?format=jpg&name=large)

回到插件页，顶部多了「已安装」和「发现」两个标签。切到「发现」，点搜索框左边的市场菜单，选「管理索引源…」：

![Image](https://pbs.twimg.com/media/HVKkVt8WIAAC8x9?format=jpg&name=large)

在弹出的「索引源」窗口里，粘贴社区维护的「开放插件市场」索引地址，点「添加」：

```text
https://dshopen.org/index.json
```

![Image](https://pbs.twimg.com/media/HVKkVsqXEAAX1yo?format=png&name=large)

窗口下方那行提示要记住：**索引由第三方提供。只添加你信任的来源：其中的插件安装后以你的权限运行。** 这个索引不是 DeepSeek 官方维护的，DSH 只检查索引格式，不替你验证每个插件。

添加完成，「发现」页就能直接浏览了：

![Image](https://pbs.twimg.com/media/HVKkVu9XgAAx_IB?format=jpg&name=large)

- 我截图当天，这个索引收录了 785 个插件；
- 分类有工具、工作流与协作、集成、记忆、技能、界面、开发与运维、模型供应商、外观、用量与费用、知识与研究；
- 每张卡片会标下载量、最近更新、更新勤，部分插件还有「经过验证」标记；
- 右边的「安装」点一下，确认来源后就能装。

**这条路的好处是不用先装任何第三方插件。** 市场入口是官方的，只有索引是社区的，以后想换别的索引，在「管理索引源…」里加一个地址就行。

## 3\. 添加插件：包名、GitHub 地址、本地目录都行

市场里没有的插件，点插件页右上角「添加插件」手动装：

![Image](https://pbs.twimg.com/media/HVKkVu0WAAESGTF?format=png&name=large)

输入框里可以填三种东西：**插件的包名、GitHub 仓库地址，或者本地目录路径。**

右下角的「安装源」默认是「中国大陆镜像源」，国内装插件不用额外配代理。

下面那段黄色提示一定要读：

> 请确认插件来源可信。插件在本机以你的权限运行，来源不明的插件可能损坏 DeepSeek Harness，或读取和泄露你的数据。

**插件就是代码。** 装一个插件，等于让一段别人写的程序用你的身份在电脑上跑。只装来源清楚、有人维护的插件。

装的时候还有个安全细节。我装一个插件时，安装结果里写着：

> 根据 pnpm 供应链安全策略（minimumReleaseAge），发布时间未满规定时长的版本不会被自动安装，因此本次安装的是 1.66.44，而非最新版本 1.66.45。

也就是说，**DSH 默认不装刚发布的新版本**，要等它过了一段观察期。万一某个插件的新版被人投毒，你不会第一时间中招。真想用最新版，要先卸载再手动指定版本号。

## 4\. 进阶可选：社区插件 dshmarket

官方「发现」页对新手已经够用。如果你想要一个更像应用商店的界面，再在「添加插件」里输入 dshmarket，装一个社区做的市场插件。装好以后，左侧栏会多出一个「插件市场」入口。**一个插件给界面加了一个入口，这就是“界面也是插件”。**

![Image](https://pbs.twimg.com/media/HVKkVvZXsAALIzP?format=jpg&name=large)

它的页面更像应用商店：有发现、主题、收藏、已安装、已屏蔽等标签，我截图时「全部」显示有 6.3k 个插件。还有一行小字很贴心：**已隐藏 547 个与 DSH 0.2.1-rc.2 不兼容的插件。** DSH 更新频繁，插件版本跟不上很正常，市场会自动帮你过滤掉装了也跑不起来的。

两个市场怎么选，一句话：

|  | 官方「发现」页 | dshmarket |

## 5\. 5 个可以挑着试的插件

市场里几百上千个插件，第一次不用挨个看。下面这 5 个是给你多几个选择，按自己的需要挑一两个试就行，不用全装。GitHub 地址都可以直接粘进「添加插件」，也可以在市场里搜名字一键安装。

**1、dshmarket：不用再到处翻 GitHub**

[github.com/dsh-market/dsh-market](https://github.com/dsh-market/dsh-market)

就是上面第 4 节那个社区市场。可以搜索社区插件、查看介绍和一键安装，适合用来挖掘各种新玩法。官方「发现」页够用的话，可以先不装。

**2、billion-context：长对话也能找回细节**

[github.com/ranxianglei/billion-context](https://github.com/ranxianglei/billion-context)

把长对话分层压缩，需要时还能找回之前的细节，适合长时间运行的 Agent 任务。重点是尽量减少上下文消耗，又不丢掉关键记忆。

**3、dsh-ops：少让 Agent 在命令行里反复踩坑**

[github.com/t-auto/dsh-ops](https://github.com/t-auto/dsh-ops)

给 Windows 补上 Bash、PowerShell 7 和高效文件工具，减少命令执行失败和反复重试带来的浪费。不过目前仅支持 Windows x64，Mac 用户可以跳过。

**4、dsh-free-search：不只依赖官方搜索**

[github.com/DDDMUC/dsh-free-search](https://github.com/DDDMUC/dsh-free-search)

DSH 默认的网页搜索依赖 DeepSeek 官方 API Key。这个插件支持 Bing、DuckDuckGo、SearXNG 等多个搜索后端，还能自动回退，部分引擎不需要 API Key，适合折腾不同的搜索方案。

**5、DSH-better-sidebar：直接把 Harness 变成开发工作台**

[github.com/omdsh-dev/DSH-better-sidebar](https://github.com/omdsh-dev/DSH-better-sidebar)

一个开放的侧边栏底座，内置文件渲染编辑、终端、侧边对话、Git 和子代理页面，其他插件还能往里注册新的侧边栏页面。装上以后，DSH 更像一个完整的开发工作台。

**装插件的顺序建议：先把市场接上，再一个一个加。** 每装一个，先开一个新会话试一下，确认没出问题再装下一个。一次装五个，出了问题你都不知道是谁干的。

# 五、拆开看：“一切皆插件”到底怎么拼起来的

这一部分稍微硬核一点，但搞懂了，你就知道 DSH 和别家的根本区别在哪。不想看原理的，可以直接跳到第六部分。

## 1\. 四个关键词：插件、组合包、模式、Profile

把 DSH 想象成一套乐高：

> **插件**是一块积木：一个工具、一个模型适配器、一个界面入口；

> **组合包（bundle）**是一袋积木：把几块相关的插件和它们的默认配置打包在一起，比如插件市场详情页里的「包含的组件」；

> **Agent 模式（preset）**是一份搭建说明：这次对话用哪些工具、什么提示词、哪些技能。标准、PTC、极简、创造四种模式，本质上就是四份不同的插件清单；

> **Profile** 是你最后搭出来的整台机器：按顺序叠加若干组合包，最上面再盖一层你自己的修改。

## 2\. 你的所有修改，都落在一个文件里

不管你是在设置页改模型、改模式，还是装插件，最后都会写进 cordis.patch.yml。设置页右上角的「打开配置文件」就是打开它。

比如，接一个 OpenAI 兼容的中转站，配置长这样：

```yaml
- id: llm-pi-ai
  config:
    providers:
      my-gateway:
        apiKeyEnv: GATEWAY_API_KEY
        api: openai-completions
        baseURL: https://gateway.example/v1
        models:
          - id: legacy-chat
```

一般人用设置页的表单就够了，不需要手写 YAML。但这个设计的意义在于：**界面能做到的事，配置文件都能做到；配置文件能做到的事，不需要改一行源码。**

用命令行版的人，还可以运行：

```sh
npx @deepseek-ai/dsh --profile web --dump-config
```

它会打印出完整的插件树。官方文档的原话是：**它打印出的任何条目，都可以由你自己的 patch 替换。**

## 3\. 冷知识：DSH 的模型层用的是 Pi 的零件

细看上面那段配置，第三方模型那一层的插件叫 llm-pi-ai，它把请求路由到 pi-ai 提供方，也就是 Pi Agent 那套模型接入库。

所以 Anthropic、OpenAI、Kimi、GLM 这些提供方，DSH 是直接复用了现成的生态。这也是“一切皆插件”的另一面：**能复用的零件就复用，自己只做拼装的框架。**

# 六、小白第一次开工：先跑两个任务

第一次不要同时开定时、插件、子智能体。先在练习文件夹里，让 DSH 只完成一种结果；你能打开、能检查，再做下一种。

动手前，在练习文件夹里再建两个子文件夹：input 放材料副本，output 放 DSH 生成的结果。原文件留在原地，第一次操作出错也不会丢东西。

所有练习都走同一条路：

1. 点「新会话」，工作区选这个练习文件夹；
2. 模式选「标准模式」，权限保持「工作区内修改」；
3. 粘贴提示词，替换【方括号】里的内容；
4. 发送后先看它准备怎么做；
5. 完成后去 output 打开结果；
6. 不放心的地方，切到「轨迹」看它每一步到底干了什么。

一条能执行的任务，至少写清四件事：**材料、任务、约束、验收**。

## 1\. 让它整理一批文件

```text
读取 input 文件夹里的所有文件。
按内容主题分成 3 到 5 类，在 output 里生成一份 Markdown 清单：文件名、所属分类、一句话摘要。
只读取，不移动、不改名、不删除 input 里的任何文件。
验收：清单里的文件数量和 input 实际文件数量一致，并在回复里写出这两个数字。
```

完成以后，先数一下 input 有几个文件，再看清单里是不是同样多。数量对不上，就让它把漏掉的列出来。

## 2\. 让它批量处理，再汇总（试试 PTC 模式）

这类任务正好用来感受 PTC 模式和标准模式的区别。新开一个会话，模式切到「PTC 模式」：

```text
读取 input 里所有【CSV / Excel】表格。
把它们合并到一个新文件 output/汇总_v1.xlsx，保留原始数据页；新增“汇总”页，按【月份】和【类别】统计数量与金额。
去掉完全重复的行，无法判断的行单独放进“异常”页，不要删除。
不要修改原文件。
验收：在回复里写出原始总行数、去重后行数、异常行数和汇总金额。
```

处理 Excel 时，可以去轨迹里看看它有没有用上前面说的 office-xlsx 技能。验收时先看原始行数对不对，再看汇总金额，最后点开“异常”页确认它没有偷偷删数据。

## 3\. 有余力的话：进创造模式试试

前两个任务跑顺了，想感受一下“一切皆插件”，可以新开一个会话，模式切到「创造模式」试试，比如：

```text
我想给 DSH 加一个很小的功能：一个叫 word_count 的工具，输入一个工作区内的文件路径，返回这个文件的字数和行数。
先告诉我你打算怎么实现、会新建哪些文件，等我确认后再动手。
不要修改 DSH 自带的任何插件。
```

这一步不是必修课。能跑通最好，跑不通也不影响你日常用 DSH 干活。试完不想要了，去插件页停用或卸载就行。

## 4\. 还有哪些事可以直接交给它

- **读代码、修 bug**：让它看仓库结构、定位问题、改代码、跑测试；
- **整理资料**：Word、Excel、PPT、PDF、Markdown 都能读，结果另存新文件；
- **长任务**：用 /goal 给会话设一个持久目标，它会跨多轮自动推进，默认最多续跑 256 轮，可以随时暂停；
- **定时提醒**：每天固定时间查一件事、提醒一件事；
- **分包给别的 Agent**：开启 Claude Code / Codex 子智能体，把独立子任务交出去；
- **接 MCP**：官方给了几份接入记忆类 MCP 服务的参考配置，工具会以 mcp\_\_服务名\_\_工具名 的形式出现；
- **命令行一次性任务**：npx [@deepseek](https://x.com/@deepseek)\-ai/dsh headless "run the tests"，跑完打印结果就退出，适合写进脚本。

看到完成提示后，至少检查三件事：文件能打开、结构符合要求、关键数字能回到原材料。需要返工时让它另存 v2，不要覆盖第一版。

# 七、国内用户最关心的两件事

## 1\. 网络：账号登录和装插件都不用梯子

用 DeepSeek 账号或官方 API，国内直连没问题；装插件默认走中国大陆镜像源，也不用代理。

只有接海外模型，或者让它联网搜索、抓海外网页时，才需要代理。这里有一个很多人踩过的坑：**浏览器能翻出去，不代表 DSH 能翻出去。**

DSH 读的是 HTTPS\_PROXY 和 HTTP\_PROXY 这两个环境变量，不读系统代理设置。官方文档给的写法是：

```sh
export HTTPS_PROXY=http://127.0.0.1:7890
export HTTP_PROXY=http://127.0.0.1:7890
```

端口换成你自己代理软件的端口。也可以写进 ~/.dsh/.env，和 API Key 放在一起。

安全上有个细节很加分：**项目文件夹里的 \`.env\` 不能设置代理。** 因为别人仓库里的 .env 会跟着 git clone 一起下来，DSH 宁可拒绝启动，也不让一个陌生仓库决定你的流量往哪走。

## 2\. 安全：它很开放，所以你要更小心

前面已经看到，DSH 在几个地方都替你设了防：登录页提醒你确认客户端、添加插件时提醒你确认来源、安装时默认不装刚发布的新版本。

但官方安全说明写得很坦白：沙箱、审批提示和权限控制可以降低风险，但不保证隔离。它给的建议是：

1. 只给最小必要的权限和访问范围；
2. 优先在一次性虚拟机、容器或专用环境里运行；
3. 备份它能访问到的文件；
4. 不要把敏感凭据和数据暴露给它；
5. 允许运行之前，先检查插件、配置和准备执行的命令。

还有一个第三方研究可以参考。8 月一篇 arXiv 论文专门测了 DSH 对**间接提示词注入**的抵抗力，也就是把恶意指令藏在网页、文件里，诱导 Agent 执行。研究跑了 14,560 次受控测试，覆盖 16 种内容渠道；其中“隐藏 Unicode 字符藏在文件里”这种手法，攻击成功率达到 25.5%。

这不是 DSH 独有的问题，所有能读文件、能联网的 Agent 都面临同样的风险。但它提醒我们：**让 Agent 读一份陌生文件、一个陌生网页之前，权限别开太大。**

# 八、已经用过 Pi、Claude Code 或 Codex，DSH 怎么选

## DSH 和 Pi

这两个我都用了挺长时间，之前也专门发过一条对比。本质上是同一类东西：都给你一个能跑起来的 Agent 壳子，模型和工具自己往里接。

区别在出发点：

- **Pi 默认极简**，系统提示词很短，哪里不舒服就补 Skill、写扩展；
- **DSH 一上来就给一套完整的架子**，连 Harness 自己的核心都能替换。光问一句「你是什么模型」就要 9.2K token，也能看出这套架子有多完整；
- **Pi 更像角色编辑器，DSH 更像把“怎么造 Agent”整套开源了出来。**

## DSH 和 Claude Code、Codex

| 对比项 | DeepSeek Harness | Claude Code / Codex |
| --- | --- | --- |
| 源码 | 完全开源，MIT | Codex 开源（Apache-2.0），Claude Code 不开源 |
| 上手门槛 | 国内账号登录即用，中文界面 | 需要海外账号或额外配置 |
| 模型 | 任意接入，DeepSeek、Claude、GPT、Kimi、GLM、中转站都行 | 默认用自家模型 |
| 可改程度 | 连 Agent 循环都能从配置替换，社区插件上千个 | 能装 Skill、接 MCP；想改核心要直接改源码 |
| 过程可见 | 轨迹视图看每一步、每一段上下文 | 主要看对话里的输出 |
| 成熟度 | 预览版，经常有破坏性更新 | 成熟稳定 |

## 普通人如何选择？

我的建议是看你想要的是“工具”还是“工作台”：

- **只想今天就把活干完，又能稳定用海外模型**：Claude Code、Codex 更稳，坑更少；
- **想要一个干净、自己慢慢加东西的底盘**：Pi 更合适；
- **想用国产模型、想看清 Agent 每一步在干什么、想自己改造 Agent**：DSH 最值得花时间；
- **已经在用 Claude Code / Codex，又想试试 DeepSeek**：DSH 不用二选一，项目里的 AGENTS.md、CLAUDE.md 和 .agents/skills 它都直接认，还能把它俩当成 DSH 的“外包”。

# 九、小白最适合的升级路线

不要第一天就把插件市场、完全权限、定时任务、子智能体全部打开。按下面五级升级，哪里出错都容易找：

1. 装好桌面版，用 DeepSeek 账号登录，建一个练习工作区，只让它读和总结；
2. 读取副本文件，输出一个新文件，学会看轨迹；
3. 打开「自定义插件市场」接上开放插件市场，从推荐的 5 个插件里挑 1 个试试；
4. 手动跑通一次后，再建一条定时任务；
5. 单次任务稳定后，再进创造模式写插件、开子智能体、接 MCP。

你今天只需要完成前两级。

新建一个练习文件夹，放入一份没有敏感信息的材料，然后发出第一条任务：

```text
读取这个文件夹里的文件，只做内容梳理。
把结果保存为一个新的 Markdown 文件，不覆盖原文件。
先告诉我你打算怎么做；完成后列出新增和修改的文件。
```

做完以后切到「轨迹」，从第一条看到最后一条。你会第一次清楚地看到：一个 Agent 到底是怎么“想一步、做一步”的。

别的 Agent 给你一辆车，DeepSeek Harness 给你一座车间。

**先用它干活，再拆开看它怎么干活。**

DSH 更新很快，后面有新插件、新玩法，我会继续在 X 上更新。
