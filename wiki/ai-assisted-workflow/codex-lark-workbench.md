## 摘要

作者放弃自建的 DeepSeek Harness 创作工作台，改用 Codex + 飞书 CLI：用项目级 Skill 提供"意图路由"来操作飞书多维表格，用现成的多维表格视图替代手写前端，并把工作台从个人看板演进成跨 Agent、跨端共享的云端知识库。

---

## 要点

- 放弃自建工作台的两个理由：一是**入口统一**（日常开发都在 Codex，不想在工具间来回切换）；二是**长链条任务稳定性**（字幕微调、临时改发布标签等需要上下文的场景，GPT 类模型精度与稳定性更高）。
- 真实需求只是"能直观呈现选题状态的看板"：随手记标题、补大纲 / 脚本 / 参考链接、排发布日期——飞书多维表格 + 飞书 CLI 恰好覆盖，还省去维护界面。
- 飞书 CLI 通过"让 AI Agent 安装"标准化完成；安装后在会话里输入 `/lark` 就能看到封装好的飞书 Skill，可直接操作日历、云文档、多维表格。
- 项目级 Skill（如 `lark-oil-media`）提供**意图路由**：预先配置表格 ID 与字段映射，Agent 不必搜索工作区或遍历字段，直接按映射写入数据行。
- 复用多维表格胜过自建前端的两个压倒性优势：**开发成本极低**、**数据结构演进成本低**（加字段 / 改视图无需同步改前端代码）。
- 跨 Agent 通用 + 云端同步：飞书 CLI 不绑定特定 AI 编辑器；数据存云端，手机端也能记灵感，豆包助手可读工作区内容；本质是为本地 Agent 补齐云端持久化，形成人与 Agent 共享的中台。

---

## 详细内容

### 为什么放弃自建工作台

作者此前用 DeepSeek Harness 搭过一套自媒体创作工作台，初衷是把散落在本地目录的视频脚本和草稿组织起来、可视化推进选题、让 Agent 协助排期。使用一段时间后，他把创作与选题管理整体迁到 **Codex + 飞书 CLI**。两点考虑：

1. **工作入口统一**：大部分日常工程和开发都在 Codex 完成，再单开一个工具处理自媒体会导致频繁切换；
2. **复杂长链条任务的稳定性**：生图、生成字幕这类被封装成单一脚本的任务弱模型也能做，但字幕微调、临时更改发布标签等需要联系上下文前后调整的场景，GPT 模型的精度与稳定性明显更高。

真实需求其实很简单：一个能直观呈现选题状态的看板——冒出灵感时快速记标题，随时补大纲、脚本、参考链接，并排发布日期。飞书多维表格 + 飞书 CLI 正好覆盖，还省去自己维护界面的麻烦。

### 飞书 CLI 的配置与项目级意图路由

飞书 CLI 安装流程标准化：在官网选择"通过 AI Agent 安装"，把指令复制给 Agent，即可在本地完成安装与身份授权。安装后，在 Agent 会话输入 `/lark`，就能看到一系列封装好的飞书 Skill，通过子命令直接操作飞书日历、云文档及多维表格等资产。

作者本地维护一个 `oil-social-media` 目录，内含专为该场景编写的 Skill `lark-oil-media`。它的核心作用是提供明确的**意图路由**：告诉 AI Agent 多维表格结构如何规划。这样当他要求"新增一个关于模型对比的选题"时，Agent 无需搜索整个工作区或遍历字段，而是直接读取 Skill 中配置好的**表格 ID 与字段映射**，准确写入对应数据行。

飞书有完整 Web 端，可在 Codex 内置浏览器 / 侧边栏固定表格：让 Agent 批量更新进度时，侧边栏实时渲染修改后的多维表格，作者也能随时手动拖拽卡片，双向操作流畅。

### 为什么多维表格比自建前端更划算

多维表格主要配置三个核心视图：**表格视图、日历视图、看板视图**，结合飞书自带数据看板（可把发布记录汇总成折线图和指标卡），几乎覆盖个人工作台的所有场景；日常零散待办也可统一放这里排期。

相比从零手写前端工作台，复用多维表格有压倒性优势：

1. **开发成本极低**：自建一套支持富文本编辑、日历联动、看板拖拽的前端系统需要大量工程时间调试组件兼容性；而飞书里基于已有字段新建看板视图只需点几次鼠标，布局与交互都现成。
2. **数据结构演进成本低**：自建系统每次业务变化（如新增"审核状态"单选框、给选题补"关联链接"字段）都要同时改底层数据格式与前端组件代码；多维表格里可随时在列菜单增删字段，对既有数据无破坏。

结论：理想个人工作台要同时兼顾"人"的交互体验与"Agent"的调用便利——让 Agent 读写只需一套 CLI，让人用着舒服则需要扎实的前端打磨；飞书表格与文档组件本就为多人协作设计、成熟度高，没必要重复造轮子。

### 跨 Agent 通用性与移动端协同

飞书 CLI 是标准命令行工具，不绑定任何特定 AI 编辑器：Codex、DeepSeek Harness、Cursor 或其他支持终端调用与 Skill 安装的环境都可复用；即便将来换编程客户端，工作台数据与路由规则也能平滑迁移。

创作流程中很多动作可自然串联：做演示文稿时，让 Agent 从多维表格提取选题大纲，由 Codex 写成 HTML 演示文稿，再调用飞书命令把 HTML 挂载进对应云文档，成品文件一并归档。

跨设备同步是更重要的一点：飞书数据天然存云端，通勤 / 外出时若突发选题灵感，可直接在手机 App 点加号写入；移动端内置的豆包助手也支持读取工作区文档与表格，不方便敲键盘时可用语音检索资料或补充大纲。

### 从个人工作台演进为 Agent 云端知识库

飞书个人版对个人用户免费，若只当排期记录板就低估了它。更合理的定位是把它当作**多个 AI Agent 之间的云端中枢知识库**：当不同设备上的本地 Agent 都配置了飞书 CLI 后，实际上为本地模型补齐了云端持久化能力。本地 Agent 不再局限于某台电脑的硬盘目录，可把处理完的文档、配置和任务状态沉淀到飞书云端；换设备工作时，接手的 Agent 都能通过 CLI 读到最新上下文，成为人与 Agent 长期共享的工作中台。
