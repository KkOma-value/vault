## 摘要

UI（用户界面）设计关注"界面看起来怎样"，UX（用户体验）设计关注"产品用起来效果如何"。两者常被混为一谈，但关注点、思维方式、原型细节、使用工具和所需技能都不同；它们需要协作，却最好各自专精。

---

## 要点

- UI = 界面外观（按钮、布局、动画、转场、微交互），UX = 全生态交互与整体体验。
- UI 设计师关注视觉呈现，画高保真彩色原型；UX 设计师关注目的与功能，画黑白线框草图，更偏宏观项目管理与分析。
- 常见界面形态：GUI（图形界面）、VUI（语音界面）、手势识别界面（面向 VR 等 3D 空间）。
- UX 流程核心是交互设计、用户研究、信息架构；优秀 UX 要易上手、能解决问题、覆盖不同用户群体、体验积极。
- 让一个设计师同时承担 UI/UX 双角色代价高：需要不断在概念与视觉之间切换，两边投入都被摊薄；最好专精其一。
- 认知偏差（cognitive bias）会显著影响体验，许多营销策略正是利用了它们。

---

## 详细内容

### UI 设计——界面外观如何

UI 关注软件图形界面，包括按钮、布局、动画、转场、微交互等。简而言之，UI 关于界面外观。常见界面类型：

- **GUI（用户图形界面）**：设计用户与系统控制工具之间的视觉交互，例如电脑桌面。
- **VUI（语音用户界面）**：设计用户与系统的语音交互，例如 Siri、Bixby。
- **手势识别界面**：面向 VR 及基于手势的系统，用户面对 3D 空间。

优秀 UI 的目标：帮助用户以最小努力完成任务、赏心悦目、传达品牌价值。

### UX 设计——产品效果如何

UX 关注用户与系统全生态的交互，符合逻辑的导航和自然丝滑的体验都属于 UX。核心流程包括：

- **交互设计**：用户如何使用组件（页面转场、动画、按钮等）来完成任务。
- **用户研究**：收集新老用户反馈，理解需求并据此设计。
- **信息架构**：厘清内容类别关系、合理安排内容层级，便于用户完成任务。

优秀 UX 的标准：易上手、能解决用户问题、满足不同用户群体、带来积极体验。

### 主要区别

尽管终端产品同时受益于两种设计，但它们的过程差异很大：

- **关注点**：UI 关注终端视觉呈现，做高保真原型，处理微观细节；UX 关注产品的目的、功能与内在逻辑，更偏宏观项目管理与分析。
- **原型细节**：UI 画彩色高保真原型，UX 画黑白草图 / 线框。
- **工具**：UI 常用 Sketch、Flinto、Principle、InVision、Photoshop、Figma；UX 常用线框图工具如 Mockplus、Axure。
- **能力取向**：UI 需要艺术成分（关系视听体验）；UX 需要更多社会属性（理解用户想要什么体验）。

### 角色与协作

- UI 设计师：适应敏捷、能画交互流程 / 线框 / 原型、熟悉绘图工具、能用 HTML5/CSS3/JavaScript、完成从构思到交付视觉的全流程、与 UX / 开发 / 测试 / 产品协作、做响应式设计。
- UX 设计师：深刻理解体验流程、能用原型工具、具备解决问题能力和好奇心、管理利益相关方、产出流程图 / 线框 / 站点地图 / 原型、与多方紧密合作并迭代、制定体验策略、跨终端设计无缝交互。

协作上，UX 通常更早介入（用户分析、项目管理），UI 再依据 UX 草图做美学与交互设计。**只做 UI 没有好 UX 会导致导航笨拙；只做 UX 没有好 UI 则难以吸引用户。**

### 混淆 UI/UX 的弊端

同时承担两个角色像"同时戴两顶帽子"：需要不断在概念与视觉之间切换，既困难又摊薄了两边的时间精力。虽然很多公司招聘身兼两职者（报酬也可能更高），但两个角色难以平衡，通常建议专精一个方向——有艺术细胞、懂色彩更适合 UI；擅于管理用户与利益相关方、分析能力强更适合 UX。

### 认知偏差

优秀 UX 设计师需要时刻注意人天生存在的认知偏差，这些偏差会影响使用体验，许多营销策略正是利用了它们。
