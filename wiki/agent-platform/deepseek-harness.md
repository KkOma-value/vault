## 摘要

DeepSeek Harness（DSH）是 DeepSeek 于 2026 年 8 月 13 日开源的 agent harness（MIT），定位为「模型是大脑，Harness 是身体」中的身体：把模型接到文件、终端、浏览器与工具上，并管理对话历史、权限确认与上下文压缩。它最大的差异点是**一切皆插件**——底层基于 Cordis 插件框架，模型适配器、工具注册表、会话存储、界面入口乃至 agent loop 本身都是可替换插件，不存在「需要打补丁的特权内核」，且能运行中装卸。配合轨迹（append-only 会话记录）、三种权限档位、四种 Agent 模式与开放的插件市场，DSH 把「怎么造 Agent」整套暴露给用户；代价是仍为预览版、常有破坏性更新、未经安全审计。

---

## 要点

- **范式**：与「整机式」Agent（能装 Skill/接 MCP，但核心写死）相反，DSH 把模型适配器、工具、会话日志、界面和 agent loop 全部做成插件；官方原话是「不存在特权内核」。
- **上手门槛低**：桌面版（macOS Apple 芯片 / Windows 64 位）用 DeepSeek 账号登录即可，无需梯子、无需 API Key；也可用 `npx @deepseek-ai/dsh web` 在 127.0.0.1:3080 启动网页版。
- **可见性**：轨迹页把每次请求的完整上下文摊开（系统提示、技能目录、时间/时区、工作目录），支持恢复、fork、搜索与回放，是排查 agent 行为的主要证据。
- **可改造**：所有设置最终落到 `~/.dsh/profiles/<profile>/cordis.patch.yml`；`npx @deepseek-ai/dsh --profile web --dump-config` 打印的每个条目都可由用户 patch 替换。创造模式下可让 Agent 自己写插件、造模式。
- **生态复用**：模型层插件 `llm-pi-ai` 直接复用 Pi Agent 的模型接入库，因此 Anthropic、OpenAI、Kimi、GLM 及 OpenAI 兼容中转站都能接。
- **互操作**：直接读取项目里的 AGENTS.md、CLAUDE.md 和 `.agents/skills`；还能把 Claude Code / Codex 作为子智能体「外包」子任务。
- **风险**：预览版，README 明示将有破坏兼容性的变更，安全说明写明未经审计、不可视为生产可用；插件以用户权限运行，社区市场索引由第三方维护。

## 详细内容

### 1. 概念定位：Harness = 身体

Agent 拆成两半：模型负责「想」，harness 负责「做」——接文件/终端/浏览器、管理历史、权限确认、上下文压缩。同一模型换不同 harness，干活水平差别很大；Claude Code、Codex、Pi、OpenCode 本质都是 harness。DSH 自我定位就是开源 harness，而非模型。概念基础见 [[agent-platform/what-is-a-harness|什么是 Agent Harness]]。

### 2. 「一切皆插件」的边界

Cordis 插件框架下，可替换的部件包括：

| 部件 | 可替换点 |
|------|----------|
| 模型适配器 | DeepSeek ↔ Kimi/GLM/Claude/中转站，改配置即可 |
| 工具 | 读文件、Bash、搜索、定时任务等各自开关 |
| 会话存储 | 对话怎么存、存哪里可换 |
| Agent loop | 「想一步、做一步」的主循环整体可换 |
| 界面 | 侧边栏入口、标签页由插件贡献 |

插件支持运行中装卸，设计目标是「拔掉一个零件，整机照常运转」，避免 VS Code 式重启宿主。

### 3. 上手与账号模型

- **登录方式**：DeepSeek 账号（花账号余额）或 API Key（环境变量 `DEEPSEEK_API_KEY` 可自动检测）。
- **凭据存放**：API Key 只写，单独存 `~/.dsh/.credentials.yaml`，普通设置文件只留引用。
- **其他模型**：设置页「添加模型提供商」内置 Anthropic / OpenAI / Kimi / GLM；中转站或公司网关选「自定义模型 API」，支持 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages。
- **工作区**：即 Agent 能动的地盘，建议单独建练习文件夹而非交出整个桌面；与之配套的权限档位见下。

### 4. 输入框一带的控制面

**Agent 模式（预设）**：标准（默认）、PTC（批量调工具 + 结果筛选/去重/汇总）、极简（仅终端与图片读取 + 上下文压缩，用于测模型裸能力）、创造（让 Agent 写插件/组合工具与提示词造新模式）。模式不是越高级越好，极简模式缺文本编辑工具，做日常活更费劲。

**权限四档**：仅可查看 / 工作区内修改（默认）/ 完全权限 / 自动审查（实验性插件，由模型在每次工具调用前判断是否授权，仅对当前会话生效）。

**模型与推理强度**：模型决定「谁来想」（Flash 快、Pro 适合长材料多步骤），推理强度决定「想多深」（Off/Low/High/Max）；两者独立，高强度不自动纠正错误。

**计划模式**：只读分析并输出方案，必须通过界面批准动作才退出；对话里说「好的」不算批准。

**技能发现**：扫描 `项目/.dsh/skills`、`项目/.agents/skills`、`~/.dsh/skills`、`~/.agents/skills` 四处，只认一层目录；SKILL.md 需含 name（小写短横线）与 description；新增/改名/删除无需重启。与 `.agents/skills` 兼容意味着已有技能库可零成本迁移。桌面包自带 7 个 Office 技能（docx/xlsx/pptx/PDF 导出/重算/渲染）。

**自动化任务**：在对话里直接描述时间（秒后、指定时刻、每 N 分钟、每天、每周、cron），由内置定时工具落库；需人工核对频率与时区。极简模式与委派出去的子智能体看不到定时工具。

**轨迹**：会话顶部「对话 / 轨迹」双标签，按「输入、模型、工具」分层时间轴展示，记录只增不改，可看概述/预览/原始内容/来源与每步耗时、token。由设置中的「显示代码工作视图」控制是否显示。

### 5. 插件体系与市场

- **三层结构**：内置插件配置（子智能体、网页搜索、Agent 循环、终端时限/输出上限）、实验性插件（默认关闭，含智能体团队、语音输入、自动授权审查、Git 工作树、持久终端、Ralph 循环等）、已安装第三方插件。
- **官方市场入口**：开启实验性插件「自定义插件市场」后出现「发现」页，添加社区索引 `https://dshopen.org/index.json`（截图时 785 个插件，11 个分类，标注下载量/更新时间/是否验证）。索引由第三方维护，DSH 只校验格式。
- **手动添加**：支持包名、GitHub 地址、本地目录；默认走中国大陆镜像源。
- **供应链防护**：遵循 pnpm `minimumReleaseAge`，不自动安装刚发布的版本（示例：装 1.66.44 而非 1.66.45），降低新版投毒风险。
- **社区市场 dshmarket**：以插件形式提供应用商店式界面（发现/主题/收藏/已安装/已屏蔽），截图时 6.3k 插件，并自动隐藏与当前 DSH 版本不兼容的条目。
- **组合包**：官方提供 Claude Code 子智能体、Codex 子智能体组合包，让 DSH 把独立子任务分包给本机其他 Agent，只回收最终答案。

### 6. 架构四关键词：插件 / 组合包 / 模式 / Profile

- **插件**：一块积木（一个工具、一个模型适配器、一个界面入口）。
- **组合包（bundle）**：一袋积木，若干相关插件及其默认配置。
- **Agent 模式（preset）**：一份搭建说明，本质是插件清单 + 提示词 + 技能集合。
- **Profile**：按顺序叠加组合包，再覆盖用户自己的 patch。

所有修改都收敛到 `cordis.patch.yml`，其意义是：界面能做到的配置都能做到，配置能做到的不必改源码。示例配置见原文（自定义 OpenAI 兼容 provider 的 `llm-pi-ai` 段）。

### 7. 成本结构

按 token 计费，从 DeepSeek 余额扣（赠金优先）。原文价格（元/百万 token，空闲价～高峰价）：

| 计费项 | V4.1-Flash | V4-Pro |
|--------|-----------|--------|
| 输入（缓存命中） | 0.02～0.04 | 0.15～0.30 |
| 输入（缓存未命中） | 1～2 | 4.5～9 |
| 输出 | 4～8 | 13.5～27 |

高峰为北京时间工作日 9:00–12:00、14:00–18:00，其余半价。缓存命中输入比未命中便宜约 50 倍。一次「你是什么模型」就消耗 9.2K token——因为每轮都带系统提示词、工具说明、技能目录、时间与工作目录；普通 demo 约几毛钱，长任务与 Pro 才显著上升。另：DSH 内的网页搜索/抓取自 2026-11-01 起按次收费（每千次成功请求 5 元）。对应 [[agent-cost-optimization/_index|Agent 成本优化]] 的「先度量后优化」。

### 8. 网络与安全

- **网络**：DeepSeek 账号与官方 API 国内直连；插件走大陆镜像。接海外模型或抓海外网页才需代理，且 DSH 只读 `HTTPS_PROXY` / `HTTP_PROXY` 环境变量，不读系统代理；可写入 `~/.dsh/.env`。项目内 `.env` 被禁止设置代理，防止陌生仓库劫持流量。
- **官方态度**：沙箱/审批/权限只降低风险、不保证隔离；建议最小权限、一次性 VM/容器、备份可访问文件、不暴露敏感凭据、执行前审查插件与命令。
- **实证风险**：2026 年 8 月一篇 arXiv 论文用 14,560 次受控测试测 DSH 对间接提示词注入的抵抗力，覆盖 16 种内容渠道，「隐藏 Unicode 字符藏在文件里」的成功率达 25.5%。这不是 DSH 独有，所有能读文件/联网的 Agent 同理——读陌生文件前先收权限。见 [[ai-security/_index|AI 安全]]。

### 9. 选型：DSH vs Pi vs Claude Code / Codex

| 维度 | DSH | Pi | Claude Code / Codex |
|------|-----|----|----------------------|
| 出发点 | 完整架子，核心也可换 | 极简，按需补 Skill/扩展 | 成熟编码应用 |
| 可改程度 | agent loop 可从配置替换，插件上千 | 写扩展改造 | 装 Skill/接 MCP，改核心要改源码 |
| 过程可见 | 轨迹逐步可见 | 一般 | 主要看对话输出 |
| 成熟度 | 预览版，破坏性更新频繁 | 稳定 | 稳定 |

判断标准是「要工具还是要工作台」：当天要交付且能稳定用海外模型 → Claude Code / Codex；想要干净可自建的底盘 → Pi；想用国产模型、看清每一步、改造 Agent 本身 → DSH；已在用 CC/Codex 也不必二选一——AGENTS.md、CLAUDE.md、`.agents/skills` 通用，还能互相当子智能体。

### 10. 落地路线（小白五级）

1. 装桌面版、账号登录、建练习工作区，只让它读和总结；
2. 读副本、输出新文件、学会看轨迹；
3. 接开放插件市场，从推荐插件里挑 1 个试；
4. 手动跑对一次后再建定时任务；
5. 单次任务稳定后再进创造模式写插件、开子智能体、接 MCP。

任务提示词至少写清四件事：**材料、任务、约束、验收**。实操上先建 `input`（材料副本）/`output`（结果）两个子文件夹，原文件不动；插件一次只装一个、每个新开会话验证。示例任务：文件分类清单（只读不写、验收比对文件数）、PTC 模式批量合并 CSV/Excel（去重、异常单独成页、验收总行数与金额）、创造模式加一个 `word_count` 工具。
