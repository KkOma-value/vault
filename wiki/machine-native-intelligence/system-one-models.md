## 摘要

Jev 是 TypeSafe 的旗舰模型，也是首个 **System One 模型**。它接收"状态（state）+ 类型化问题（typed questions）"，直接返回类型化结果与概率分布，代码无需解析文本即可分支、排序和路由。

---

## 要点

- LLM 面向人类产出文本；当代码要消费模型判断时，会出现"把文本生成系统硬拗成结构化决策再解析回来"的错配。
- System One 模型直接返回结构化结果（类型化值与概率分布），不生成文本、不做解析。
- 三种 AI 原语：**Choice**（从列表选一项）、**Score**（按评分标准打分）、**Noul**（判断陈述真假）。
- 三类问题可在一次 API 调用中混用，针对同一状态并行、相互隔离求值；增加问题几乎不增加响应时间，也不会产生上下文腐化（context-rot）。
- 原子化提问、在代码中组合：每个问题只问一件具体、边界清晰的事。

---

## 详细内容

### 文本生成与结构化决策的错配

LLM 被设计用来产出给人阅读的文本。当需要让模型做"代码将要消费的判断"时，就会出现不匹配：你要把文本生成系统硬拗成输出结构化决策，再把结果解析回代码能依赖的形式。System One 模型正是为消除这一层错配而生——直接做出软件可直接使用的、快速的、结构化的决策。

### Jev 的工作方式

Jev 针对一个 **状态** 评估一批 **类型化问题**，并直接返回结构化结果：不生成文本、不解析。你能拿到类型化值与概率分布，用它们做分支、排序和路由。Choice 与 Score 还会返回**置信度（confidence）**，代码可据此决定是否、以及如何依据某个答案行动。

### 三种 AI 原语

TypeSafe 暴露三种 AI 原语，它们像软件原语一样模块化、可组合、结构化、可靠且快速。每种原语问不同类型的问题、返回不同类型的答案：

| 问题类型 | 目标 | 返回 |
|---|---|---|
| Choice | 从列表中选出一个选项 | `choice`、`probabilities`、`confidence` |
| Score | 按评分标准对状态打分 | `score`、`probabilities`、`confidence` |
| Noul | 判断该陈述是否成立 | `noul`（0–1） |

三种问题可以在一次 API 调用中混用：每个问题都在同一次请求里、针对同一状态并行且相互隔离地求值。增加问题几乎不增加响应时间；每个问题独立求值，因此增加问题也不会造成上下文腐化。

### 原子化提问，在代码中组合

System One 模型在"每个问题只问一件具体、边界清晰的事"时效果最好。可以把每个问题理解成一次"直觉判断"：一个知识渊博的人在给定正确上下文后，几秒内就能做出的判断。

如果一个问题需要长时间推理，或它同时权衡了多个独立因素，就应**拆解**它：把每个因素作为单独的问题提出，然后在代码里用逻辑组合结果。这样既能保证每个单独评估可靠，也让你完全掌控各维度的权重。

例如，不要问"给这个创业点子打分"，而是分别问市场大小、技术可行性和差异化程度，再用自己的公式组合得分。当优先级变化时，你只需改代码里的一个系数，而不必重写 prompt。
