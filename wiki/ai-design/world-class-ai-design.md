## 摘要

AI 设计之所以容易产生“通用 slop”，不是模型不会执行设计规则，而是语言模型倾向于逐 token 选择最安全、最常见的方案。要获得有辨识度的结果，应把设计过程拆成 **Discover（发散探索）—Define（建立独特方向）—Deliver（删减与打磨）**：用外部随机种子和大胆 brief 扩大创意空间，用独立 critic 与多模型循环建立质量反馈，再用克制、原生组件和有目的的视觉素材完成收敛。

---

## 要点

- **随机性要从模型外部注入**：让模型自己“随机”通常只是生成看似随机的常见表达；可用 shell 生成随机字符串，把它作为色彩、构图、字体或隐喻的灵感种子。
- **先宽后深**：先批量探索方向，再由人判断自己真正喜欢和反感什么；大胆、具体的设计 brief 比“做得独特一点”有效。
- **把实现和评审分开**：实现 Agent 负责快速修改，新的 critic 只看当前截图和质量基准，在新上下文中指出最大缺口；昂贵模型只承担判断，不承担所有执行。
- **用真实素材突破代码默认值**：图像生成适合补充品牌视觉，视频生成适合循环动效、物理效果和状态间过渡；素材应服务于设计方向，而不是为了堆效果。
- **交付阶段优先删除**：去掉无意义的 glow、渐变、容器、标签和装饰，优先使用合适的原生控件；留白和克制往往比增加元素更能提升质感。
- **循环必须有停止条件**：明确质量基准、先观察一两轮是否收敛，避免 critic 触发无限迭代和无效 token 消耗。

## 详细内容

### 1. 为什么默认结果趋同

语言模型按训练数据中最可能出现的下一个 token 生成内容，因此在面对开放式设计决策时会倾向于“大家都不会反对”的方案：熟悉的布局、常见的配色和安全的装饰。直接要求“完全随机”并不能真正改变这个机制。设计者需要提供额外的探索压力，以及明确的个人审美判断。

这与 [[designing-with-ai|品味驱动的 AI 设计工作流]] 相互补充：前者强调人提供意义、方向和品味，本文进一步把探索、评审和收敛组织成可重复的 Agent 流程。

### 2. Discover：扩大可能性空间

#### 随机种子

在 brief 中要求 Agent 先通过 shell 生成较长的随机字母数字串，再从其中寻找数字、重复片段或其他模式，映射到色彩、排版、布局和视觉隐喻。种子不应出现在最终设计中，它只是一个外部扰动源，让每次运行拥有不同的创意起点。

#### 大胆的设计 brief

“做一个生产力产品落地页”会把模型推回熟悉模板。更有效的 brief 会提供有张力的参考方向，例如像素游戏、等距城市、工业控制台、极度不对称的布局或有意制造的不适感，同时说明仍需满足的产品目标。好的约束不是让模型更保守，而是给它足够具体的世界观。

如果自己暂时没有方向，可以让 AI 先列出大量简短、低细节的方向；人先筛选并描述真实反应，再让 AI 根据这些偏好收敛，最后才请它写成用于实现的初始 prompt。不要把第一轮 AI 点子原样喂回去，否则不同人的结果仍会趋同。

### 3. Define：建立个性与反馈回路

初稿即使有潜力，也常保留导航栏、左文右图、CTA 等默认结构。此时可建立“实现 Agent + 设计 critic”的正反馈回路：

1. 截取当前设计的截图。
2. 在新上下文中只给 critic 截图和设计目标，不给代码、实现细节或旧的自我辩护。
3. 要求 critic 从整体构图到细节层级，判断设计是否兑现目标风格，并列出最重要的具体缺口。
4. 让实现 Agent 只处理高价值问题，再进入下一轮。

critic 的标准要尽量客观：提供专业参考图作为质量基线，要求识别过度使用的 AI 模式，并要求给出可比较的评分或排序。大模型适合做少量高价值判断，小模型适合执行重复修改；不要让 critic 直接重做全部页面，也不要把“达到 9/10”之类的内部停止条件写进评审标准，以免诱导评分。

### 4. 用图像和视频补足视觉表达

代码 Agent 容易用渐变、几何形状和基础 pattern 替代真正的视觉素材。针对具体品牌和构图生成图片，可以增加设计的独特性；循环视频则可用于玻璃、光影、物理运动等复杂效果。视频模型还可以用首帧/尾帧生成页面状态之间的过渡，并根据滚动或手势逐帧播放。

生成素材时要把页面背景、色彩和用途一起提供给模型，必要时先在目标背景上生成再做抠像或 matting，以保持光影一致。API key 应使用受限额度的本地环境变量或 gitignored 文件，不能写入代码、产品或公开 prompt。

### 5. Deliver：用减法达到生产质量

AI 通常擅长添加内容，却不擅长删除。交付前应逐项追问每个元素是否承担信息、交互或情绪价值：

- 删除只负责“看起来高级”的 glow、渐变和随机高亮。
- 删除图片已经表达却被文字重复说明的标签和空容器。
- 优先使用平台原生控件，不为追求独特而重造更差的按钮和输入框。
- 保持文字更小、更紧凑，让核心视觉承担应有的表达。

最终质量来自有取舍的判断，而不只是更长的 prompt 或更多的代码。
